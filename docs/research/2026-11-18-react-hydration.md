# Research: hydrating the prerendered landing and checking it automatically

Version 1.0.0 · 2026-11-18

## Question

How should the landing attach React to the HTML that `scripts/prerender.mjs` renders, keep
client-only state (theme, OS, language, clock) without mismatches or a colour flash, and catch
a mismatch automatically with the least CI cost?

## Findings

- [1] "If your app's HTML was generated by `react-dom/server`, you need to hydrate it on the
  client." "`hydrateRoot()` expects the rendered content to be identical with the
  server-rendered content. You should treat mismatches as bugs and fix them." For intentional
  differences it shows two-pass rendering (state set in an Effect). `onRecoverableError` is
  called "when React automatically recovers from errors".
- [2] `getServerSnapshot` is used during server rendering and hydration; React then
  re-renders with `getSnapshot` on the client. That is the documented way to read a browser
  value without a mismatch, and it fits values outside React (the `data-theme` attribute set
  by the boot script, the user agent).
- Verified in this repo with React 18.3.1 development build: text and attribute mismatches
  are reported through `console.error` ("Text content does not match…", "Extra attributes
  from the server…", "Hydration failed…") and the root is re-rendered on the client. A check
  that fails on any `console.error` catches both kinds; checking that the first root node is
  still the same object proves the DOM was hydrated, not replaced.
- [3] jsdom runs inline scripts with `runScripts: 'dangerously'` and does not load external
  ones unless `resources: 'usable'`, so the theme boot script runs as in a browser and the
  built bundle does not; `beforeParse` can seed `localStorage`, `matchMedia` and the user
  agent before that script runs.
- [4][5] `jsdom@30.1.3` requires Node `^22.22.2 || ^24.15.0 || >=26`; CI used Node 20, which is
  already end of life, so CI moves to Node 22. The Cloudflare build only runs `pnpm run build`
  and does not load jsdom.
- Playwright would add a ~150 MB browser download per CI run for no extra coverage of
  hydration (a render-output comparison); reasoned, not benchmarked.

## Mismatch sources found (`landing/src`)

| Source | Before | After |
|---|---|---|
| `useTheme` | `useState` initializer read storage/`matchMedia` | `useSyncExternalStore` on `<html data-theme>`, server snapshot `light` |
| Nav logo / theme icon class | depended on theme state | CSS `:root[data-theme='dark']` |
| `detectOS` in home/guide | `useState(detectOS)` | `useOS()`: `useSyncExternalStore`, server snapshot `linux` |
| `CodeBlock` | read `document.documentElement.lang` in render | page language prop |
| Hero `bootOffset` | `useState` initializer read `getAnimations()` | removed |
| `useLangRouting`, `LangSuggest`, TmuxBar clock, Hero uptime | effects only / render after effect | unchanged (safe) |
