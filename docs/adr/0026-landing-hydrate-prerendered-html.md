# ADR-0026: Landing hydrates its prerendered HTML (hydrateRoot) with a hydration check in CI

Version 1.0.0 · 2026-11-18

Status: Accepted · Date: 2026-11-18 · Decision-makers: project maintainer

Supersedes the boot-timeline part of [ADR-0024](0024-landing-motion-a11y-performance.md)
(option 3, `getAnimations()` resume); the rest of ADR-0024 stands.

## Context and Problem Statement

`scripts/prerender.mjs` renders every page × language with `react-dom/server` into the built
HTML, but each entry then called `createRoot`, which throws that DOM away and renders it
again. React's documentation says HTML generated by `react-dom/server` must be hydrated, and
that a mismatch between the server and the first client render is a bug
([research](../research/2026-11-18-react-hydration.md)). ADR-0024 left `hydrateRoot` as a
follow-up because several components read browser-only state during render.

## Decision Drivers

- Reuse the prerendered DOM: no double render, CSS animations keep running from first paint.
- The first client render must equal the prerender, for every visitor (stored theme or
  language, any OS, dark OS theme), and the page colour must not flash.
- A mismatch must fail CI, not be found by a visitor. No browser download in CI if a lighter
  check is reliable; no new runtime dependency.

## Considered Options

1. Keep `createRoot` + `getAnimations()` resume (ADR-0024 status quo).
2. `hydrateRoot`, browser-only state read through `useSyncExternalStore` with a server
   snapshot (or in an effect), checked by a Node script with jsdom over the built HTML.
3. Same as 2, checked with Playwright in a real browser.

## Decision Outcome

Chosen: **option 2**.

- Entries (`landing/src/pages/*/main.tsx`) call `hydrateRoot`.
- Theme: `<html data-theme>` is the store. The inline boot script (`THEME_BOOT`, unchanged,
  same CSP hash) sets it before paint; `useTheme` reads it with `useSyncExternalStore`
  (server snapshot `light`) and writes it only on a pick or a live OS change, so nothing
  writes `light` back over a dark page. The nav logo and the sun/moon icon follow
  `:root[data-theme]` in CSS, so they are right before React runs.
- OS: `useOS()` = `useSyncExternalStore` (server snapshot `linux`, what the prerender shows)
  plus the visitor's tab pick.
- Copy button text: `CodeBlock` gets the page language as a prop instead of reading
  `document.documentElement.lang` in render (the prerender always said "copy").
- Already safe, unchanged: stored language and banner (`useLangRouting`, effect only; the
  banner renders only after it), tmux clock and hero uptime (start empty / 0, set in effects).
- Hero: the `--boot-offset` / `getAnimations()` compensation is removed.
- `scripts/check-hydration.mjs` (`pnpm check:hydration`, CI job `landing-ci` after the build):
  loads the real `main.tsx` of each page in jsdom over `dist/`, runs the inline boot script,
  for three visitors (default; dark + language stored + macOS; dark OS + Linux + other
  browser language). It fails on any React `console.error`/`warn` (development build, which
  reports text and attribute mismatches), uncaught/recoverable error, replaced root DOM, a
  `data-theme` different from what the boot script set, or the hero not showing the
  visitor's OS binary after hydration.

Option 3 was not needed: the mismatches here are React render output, which jsdom reproduces
exactly; layout and paint are not part of hydration. jsdom (devDependency) needs Node ≥ 22.22,
so the workflow moves from Node 20 (end of life 2026-04-30) to Node 22.

### Consequences

- Good: no client re-render of the whole page; the hero animation never restarts (no
  `getAnimations()` fallback for old browsers needed); ES pages now prerender "copiar"; a
  mismatch fails CI with the page, visitor and React message. Lighthouse mobile on `/` stays
  97 (TBT 10–22 ms → 2–8 ms, LCP ~2.3 s, CLS 0), see the research note.
- Bad: a non-default visitor (Windows/macOS, dark theme) sees the default text in a few
  places (binary name, theme button label) until hydration finishes — as before with the
  prerender; colours and icons are already correct from the boot script and CSS.
- Rule for new code: never read `window`, `document`, `navigator`, storage, `Date` or
  `matchMedia` during render or in a `useState` initializer; use an effect or
  `useSyncExternalStore` with a server snapshot. `pnpm check:hydration` enforces it.

### Confirmation

`pnpm run build && pnpm run check:hydration` → `hydration: 30 runs, no mismatch`. Negative
tests: the check fails on the old prerendered HTML (ES copy button) and when `useOS`'s server
snapshot is replaced by `detectOS()` (Windows/macOS visitors).
